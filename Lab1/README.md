# Credit Default Risk Scoring API

> **DDM501 — AI in DevOps, DataOps, MLOps | Lab 1**  
> Turning a handed-over model into a production-ready service.

---

## Overview

A Vietnamese consumer finance company's data science team trained a model that estimates the probability a credit card customer will miss their next payment. This project wraps that model in a REST API that risk operations can call in milliseconds — behaving identically in development, staging, and production.

### What this service does

1. Accepts a credit card applicant's profile (23 features)
2. Runs it through a trained `HistGradientBoostingClassifier` pipeline
3. Returns a **default probability** and an **underwriting decision**

```
probability < 0.30              → LOW    → APPROVE
0.30 ≤ probability < 0.60       → MEDIUM → REVIEW  (human underwriter)
probability ≥ 0.60              → HIGH   → DECLINE
```

## API Endpoints

| Method | Endpoint | Description |
|--------|----------|-------------|
| `GET`  | `/health` | Service liveness + readiness |
| `GET`  | `/` | API metadata |
| `GET`  | `/model/info` | Model version, metrics, thresholds |
| `POST` | `/predict` | Score one applicant |
| `POST` | `/predict/batch` | Score up to 500 applicants in one call |

### Request schema — `POST /predict`

```json
{
  "limit_bal": 300000,
  "sex": 2,
  "education": 1,
  "marriage": 2,
  "age": 38,
  "pay_status": [-1, -1, -1, -1, -1, -1],
  "bill_amt": [12000, 11500, 11000, 10500, 10000, 9500],
  "pay_amt":  [12000, 11500, 11000, 10500, 10000, 9500]
}
```

### Response schema

```json
{
  "default_probability": 0.0412,
  "risk_band": "LOW",
  "decision": "APPROVE",
  "review_threshold": 0.3,
  "decline_threshold": 0.6,
  "model_version": "1.0.0"
}
```

**Validation rules enforced at the edge (422 on violation):**
- `sex`: `1` or `2` only
- `education`: `1–4` only
- `marriage`: `1–3` only
- `age`: `18–100`
- `limit_bal`: `> 0` and `≤ 2,000,000`
- `pay_status`: exactly 6 integers, each in `[-2, 8]`
- `pay_amt`: exactly 6 floats, each `≥ 0`

## Quick Start (Local)

### Prerequisites
- Python 3.11+

### Setup

```bash
git clone <your-repo-url>
cd ddm501-lab1-starter

python -m venv .venv
# Windows
.venv\Scripts\activate
# macOS/Linux
source .venv/bin/activate

pip install -r requirements.txt
```

### Train the model

```bash
python scripts/train_model.py
```

Expected output:
```
ROC AUC : 0.7481
PR  AUC : 0.5461   (baseline = 0.2328)
Model saved → models/credit_model.joblib (218 KB)
```

### Run the API

```bash
uvicorn app.main:app --reload
```

The API is now available at `http://localhost:8000`.  
Interactive docs: `http://localhost:8000/docs`

## Docker

### Build and run

```bash
# Build image and start container
docker compose up --build

# Check health
curl http://localhost:8000/health
```

### Verify container health

```bash
docker inspect --format='{{.State.Health.Status}}' credit-risk-api
# → healthy
```

### Design decisions in the container

| Decision | Reason |
|----------|--------|
| Copy `requirements.txt` first, then source | Layer caching — `pip install` only re-runs when dependencies change |
| Run as non-root `appuser` (uid 1000) | A compromised root container = compromised host |
| Mount `./models` as a volume (`:ro`) | Model artifact stays outside the image — update without rebuilding |
| Bind uvicorn to `0.0.0.0` | `127.0.0.1` inside a container is unreachable from outside |
| HEALTHCHECK calls `/health` and checks `model_loaded` | Distinguishes "process running" from "actually ready to serve" |

## Configuration

All settings can be overridden with environment variables — the same image runs unchanged across environments.

| Variable | Default | Description |
|----------|---------|-------------|
| `MODEL_PATH` | `models/credit_model.joblib` | Path to the trained pipeline |
| `MODEL_VERSION` | `1.0.0` | Reported in every response |
| `REVIEW_THRESHOLD` | `0.30` | Below this → APPROVE |
| `DECLINE_THRESHOLD` | `0.60` | Above this → DECLINE |
| `HOST` | `0.0.0.0` | Bind address |
| `PORT` | `8000` | Listen port |
| `DEBUG` | `false` | Enable debug logging |

## Model Details

| Property | Value |
|----------|-------|
| Algorithm | `HistGradientBoostingClassifier` |
| Dataset | UCI Default of Credit Card Clients (Yeh & Lien, 2009) |
| Training rows | 24,000 (80% stratified split) |
| Test rows | 6,000 |
| **ROC AUC** | **0.7481** |
| **PR AUC** | **0.5461** (baseline: 0.2328) |
| Preprocessing | `OneHotEncoder` for SEX, EDUCATION, MARRIAGE; passthrough for numeric |
| Default rate | 23.3% |

### Training confusion matrix (at threshold 0.30)

|  | Predicted No Default | Predicted Default |
|--|---------------------|------------------|
| **Actual No Default** | 4,088 (TN) | 515 (FP) |
| **Actual Default** | 726 (FN) | 671 (TP) |

> **Note:** Thresholds (0.30 / 0.60) are **business decisions**, not model properties. They live in `app/config.py` and are read from environment variables — change them without retraining.

## CI/CD

GitHub Actions workflow (`.github/workflows/smoke.yml`) runs on every push and pull request to `main`:

1. Install dependencies
2. Verify all packages resolve to wheels (no compiler needed)
3. Validate dataset shape
4. Train the model
5. Run the full test suite
6. Build the Docker image
7. Start the container and smoke-test `/health` + `/predict`
